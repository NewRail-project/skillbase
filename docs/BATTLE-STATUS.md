# Командная битва — статус реализации

## Готово (покрыто тестами в Node)
- Игровая логика `core/battle-logic.js`: команды, резерв, замены, капитанство, голосование, очки (штраф 125% в целых числах), решающий раунд, канат, оценки.
- Контроллер хода `core/battle-game.js`: вопрос → выбор капитанов → голосование → спор (15 с) → закрытие; восстановление после перезагрузки страницы; автоматический шаг раунда.
- Запуск `core/battle-launch.js` + `launchBattle` (режим комнаты, документ битвы, ключи, поля игроков одним батчем).
- Снимок в историю `core/battle-snapshot.js` + `attachBattleToHistory`.
- Экраны: подготовка, ведущий, игрок/капитан/запасной/выбывший, проектор, канат, `ui/css/battle.css`.

## Правила Firestore (проверить `npm run test:rules` перед деплоем)
- `battleKeys`, `battleRounds` — только ведущий.
- `votes`: смена голоса владельцем, пока раунд в `voting`.
- `captainDecisions`: способ ответа (`answering`/`voting`) и решение спора (`..._tb_...`, `tiebreak`).
- `roomHistory`: один раз дописать поле `battle` (остальное неизменяемо).

## Не сделано / ограничения
1. **Решающий раунд капитанов (ТЗ §13)**: логика и контроллер есть (`resolveSuddenDeath`), экрана нет. При ничьей ведущий видит сообщение и завершает битву вручную.
2. **Отслеживание связи 60 с (ТЗ §6.1)**: heartbeat участников не подключён; выбывание — только вручную кнопкой «Выбыл».
3. **Вопросы битвы** берутся из теста Live (ТЗ §4.1 просит отдельный набор).
4. **Спорные варианты** публикуются в публичном документе (капитан должен их видеть), поэтому игроки могут увидеть, какие варианты разделили голоса поровну. Это не раскрывает личные голоса.
5. **Часы**: таймеры считаются по `serverNowMs`; при сильном расхождении часов возможна погрешность в несколько секунд.
6. **Две вкладки ведущего** одновременно не поддерживаются (нет блокировки).
7. **Оценка Live** берётся как доля набранных баллов (0..100); перевод в школьную оценку журнала не делается.
8. Не проверено на устройствах (Android, проектор), не запускался Firebase Emulator.
