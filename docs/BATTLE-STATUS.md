# Командная битва — статус реализации

## Как проходит игра
1. При создании Live ведущий включает «Командная битва после теста» (поле комнаты `battleEnabled`).
2. Live идёт как обычно. После завершения у ведущего под итогами появляется панель подготовки: набор вопросов (этот тест или другой опубликованный), количество, время, порядок, веса, распределение команд, правка составов.
3. «Запустить битву» → `room.mode = "battle"`, документ битвы, ключи (`battleKeys`), поля игроков — одним батчем. Участники автоматически получают экран битвы.
4. Вопрос → капитаны выбирают способ (сам / голосование) → голосование → спор (15 с) → результат и канат → следующий вопрос.
5. Равный счёт → решающий раунд капитанов (первый правильный ответ; повтор без лимита).
6. Итоги: личные оценки, процент подготовки, снимок дописывается в `roomHistory/{code}.battle`.

## Готово (покрыто тестами в Node)
- Логика `core/battle-logic.js`; контроллер `core/battle-game.js` (ход раунда, спор, решающий раунд, выбывание по связи, восстановление после перезагрузки).
- Запуск `core/battle-launch.js`, снимок `core/battle-snapshot.js`.
- Экраны: подготовка, ведущий, игрок / капитан / запасной / выбывший, проектор, канат, `ui/css/battle.css`.
- Связь: игрок раз в 15 с пишет `players/{uid}.updatedAt`; ведущий выбывает игрока без сигнала дольше окна восстановления (60 с + пропущенные пульсы); замена из резерва и передача капитанства автоматически.

## Правила Firestore (запустить `npm run test:rules` перед деплоем)
- `battleKeys`, `battleRounds` — только ведущий.
- `votes`: смена голоса владельцем, пока раунд в `voting`.
- `captainDecisions`: способ ответа (`answering`/`voting`) и решение спора (`..._tb_...`, `tiebreak`). Решающий раунд использует тот же документ способа ответа.
- `roomHistory`: один раз дописать поле `battle`.

## Ограничения и что проверить вручную
1. Не проверялось на Firebase Emulator и на устройствах (Android, проектор, темы).
2. Отдельный набор вопросов — только **опубликованный** тест той же организации; в списке показываются тесты текущего пользователя.
3. Спорные варианты публикуются в публичном документе (капитану нужно их видеть); личные голоса не раскрываются.
4. Пульс присутствия — запись в документ игрока раз в 15 с (~2 записи/мин на игрока, 40 игроков ≈ 80 записей/мин).
5. Две вкладки ведущего одновременно не поддерживаются.
6. Оценка Live — доля набранных баллов (0..100); перевод в школьную оценку журнала не делается.
7. Сохранение в историю возможно только если история Live уже записана; иначе ведущий видит сообщение.
