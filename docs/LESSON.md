# Открытое занятие: сценарий, практика, отчёт, история

Занятие связывает уже существующие механизмы: **материал → входной тест (Live) →
Battle → практика (две таблицы) → итоговый тест (Live) → отчёт → история**.
Новой игровой системы нет: тесты и Battle проводятся штатными страницами.

## Где что лежит

| Что | Где | Кто читает |
|---|---|---|
| План (с ключами практики) | `testKeys/lesson__{id}` (существующая закрытая коллекция) | только сотрудники организации |
| Ход занятия | поле `lesson` входной комнаты `rooms/{код}` | ведущий и участники комнаты |
| Публичное задание команды (без ключей) | `rooms/{код}/practicalTasks/{a\|b}` | ведущий, наблюдатель, **своя команда** |
| Ответы команды | `rooms/{код}/practicalSubmissions/{a\|b}` | ведущий, наблюдатель, своя команда; пишет капитан |
| Ключи ответов | `rooms/{код}/battleKeys/practical_{a\|b}` (существующее правило) | **только ведущий** |
| Решения преподавателя (черновик) | `rooms/{код}/battleRounds/practical_review` | только ведущий |
| Подтверждённый результат | `rooms/{код}/battleRounds/practical_result` + `result` в `practicalTasks` | полный — ведущий; публичный итог (баллы, верно/неверно) — команды |
| Итоговый тест | вторая Live-комната, код в `lesson.finalRoomCode` | как обычная Live-комната |
| История | `lessonHistory/{код входной комнаты}` | ведущий-автор и администратор организации |

## Безопасность практики
* Ожидаемые ответы существуют только в плане (закрытый документ) и в `battleKeys` (только ведущий).
  В публичное задание и в клиентский код участников они не попадают (`core/practical.js: splitTask`).
* Проверку выполняет **страница ведущего**: он читает ключи, сравнивает с ответами команд и подтверждает результат.
  Ученик ключей не получает ни до, ни во время проверки.
* Отправленная таблица заморожена правилами (капитан её не правит); ведущий может лишь вернуть её на доработку.
* Проверка: точное совпадение после нормализации пробелов, регистра и «ё/е»; числа с запятой/точкой, допуском и единицей;
  режим «вручную» для всего, что нельзя проверить однозначно. Нечёткого сравнения свободного текста нет.

## Правила Firestore (изменены — ТРЕБУЕТ ДЕПЛОЯ ВЛАДЕЛЬЦЕМ)
Только добавления, ни одна существующая строка не менялась:
* `rooms/{roomId}/practicalTasks/{teamId}` и `practicalSubmissions/{teamId}` (с функциями `practicalTaskDoc`, `practicalReadable`, `practicalCaptainWrite`);
* `lessonHistory/{docId}` — только `create`, `update`/`delete` запрещены.
Кейсы добавлены в `tools/rules-test.mjs` (`practicalCases`, `lessonHistoryCases`). **Перед деплоем запустите `node tools/rules-test.mjs` с доступом к Firebase** — в среде разработки это не проверялось.

## Что нельзя без серверной части (нужно согласование)
* Автоматическая проверка практики **без присутствия преподавателя** (результат сразу после отправки) требует серверной проверки
  (Cloud Function): иначе ключи пришлось бы отдать клиенту. Сейчас безопасный вариант — проверка на странице ведущего.
* Гарантия, что итог истории не подменят клиентским кодом ведущего, также требует сервера (правила лишь запрещают `update`/`delete`).

## Известные ограничения
* Время прохождения тестов в снимке Live (`roomHistory`) не сохраняется — в отчёте его нет.
* Личный вклад в практику не измеряется (таблицу вводит капитан) — отчёт пишет «не оценён».
* Практика требует команд из Battle: без Battle она пропускается автоматически.
* Материал выбирается среди тестов, у которых есть книга материала.

## Практика: ввод ведущим на доске

Кроме обычного режима (капитаны заполняют таблицы на своих устройствах) ведущий
может подготовить задания **для ввода на доске**: кнопка «Подготовить для ввода
на доске». Команды называют значения вслух, ведущий вносит их в таблицы.

- Названия частей и правильные ответы задаются при настройке занятия, как и раньше.
- Таблицы двух команд стоят друг напротив друга (на телефоне — друг под другом).
- Введённые значения хранятся в закрытом документе `rooms/{code}/battleRounds/practical_entry`
  (его пишет только ведущий; правила Firestore не менялись). В `practicalSubmissions`
  ведущий писать не может — туда пишет только капитан.
- «Проверить» превращает ввод в отправленные таблицы, считает очки по ключам
  (ручные ячейки решает ведущий), показывает предварительный результат; «Подтвердить
  результат» фиксирует его так же, как в обычном режиме.
- Поля ввода не пересоздаются при снимках Firestore: фокус и набранный текст не теряются.
- В отчёте занятия добавлены колонки «Участие», «Вклад», «Командная работа»
  (по Battle и практике; нет данных — «—») и «Рекомендуемая оценка за занятие».

## Итоговая таблица Battle

`core/battle-summary.js` строит таблицу из публичного документа битвы или снимка
истории: исход, сводка команд, статистика вопросов, участники по алфавиту.
Личные ответы не используются; число споров и личное участие есть только в снимке.
Показ: экран участника, проектор/наблюдатель, «Итоги Battle» в истории (`room-history`).
