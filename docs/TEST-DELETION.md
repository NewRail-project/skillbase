# Удаление теста из каталога и истории

Преподаватель (автор теста) и администратор организации могут удалить
тест кнопкой «Удалить» на карточке теста (страница «Мои тесты»,
`#tests`). Кнопка не показывается на чужих тестах и ученикам.

## Как работает удаление (мягкое)

Документ теста не стирается из Firestore: попытки, история и аналитика
считаются по нему. Тест помечается:

    tests/{id} → { status: "deleted", deletedAt, deletedBy, settings }

Дальше правила и списки делают остальное:

1. **Правила Firestore** (`tests.update`): статус `"deleted"` ставят
   только автор или админ организации и только вместе с
   `deletedBy == свой uid`; меняются лишь поля
   `status, deletedAt, deletedBy, updatedAt, settings`. «Воскресить»
   удалённый тест или дописать его нельзя. Жёсткое `deleteDoc` для
   tests/testKeys/attempts запрещено (`allow delete: if false`).
2. **Списки**: `listMyTests` не возвращает `status == "deleted"`, поэтому
   тест исчезает из «Мои тесты», сводки «Главная» и админ-панели.
   `listPublishedTests` читает только `published` — каталог учеников
   чистится сам.
3. **Ключи ответов**: `testKeys` и снимки версий остаются (нужны для
   проверки и аналитики за прошлое), но настройка
   `showCorrectAfterQuestion` у удалённого теста гасится, а новые
   попытки невозможны: правила `attempts.create` требуют живой
   published-тест. Студент по старой ссылке `#quiz/<id>` видит «Тест
   удалён», редактор отказывается открывать.
4. **Связанные документы** (все шаги идемпотентны — повторное удаление
   безопасно):
   - активные задания (`assignments`) с этим `testId` закрываются
     (`status: "closed"`): свои — автор, все по организации — админ;
     задания других преподавателей остаются, но попытку по ним Firestore
     уже не пропустит (тест не published);
   - открытые Live-комнаты с этим `testId` закрываются
     (`status: "closed"`, `liveState: "completed"`) — только те, где
     удаляющий является ведущим: правила rooms разрешают закрытие лишь
     хозяину. Продолжить тест в комнатах чужих ведущих уже невозможно
     (правила attempts требуют published-тест, попытки не начнутся),
     однако интерфейс при удалении сообщает, какие комнаты остались:
     тост перечисляет их коды и ведущих.
   - попытки и результаты студентов **сохраняются**: незавершённую
     попытку можно отправить, преподаватель может проверить её по
     оставшимся ключам.
5. **Аналитика** не ломается: она читает `attempts` по организации и
   `testKeys` — оба документа не тронуты.

## Проверка

    npm test                        # юнит-тесты (tests/test-delete.test.js)
    node scripts/check-imports.mjs
    npm run test:rules              # нужен firebase login (Tools Rules API)

## Действия в Firebase Console

1. **Задеплоить правила**: обновлённые `firestore.rules`
   (`firebase deploy --only firestore:rules`) — без этого мягкое
   удаление получит permission-denied.
2. Комнаты чужих ведущих с удалённым тестом, если остались, закрываются
   вручную Firestore Console: `rooms/<код>` → `status: "closed"`,
   `liveState: "completed"`. Интерфейс при удалении перечисляет их коды.
